# Gravity Golf — Physics / Simulation Porting Spec (C# core)

This document is the **implementation contract** for porting the Gravity Golf
simulation core from `src/game-core.js` to **pure C#** (no `UnityEngine`
dependency, `double` precision throughout). Scope: the first **10 campaign
levels**, `createLevelRuntime(0..9)`, with core mechanics only.

All line citations are `game-core.js:LINE` against the repository copy at
`/home/richard/WebstormProjects/gravity-golf/src/game-core.js`.

> **Golden rule for parity:** the C# core must reproduce `simulateShot`
> (`game-core.js:5074`) *frame-for-frame*, in the exact operation order given in
> §10 and §14, using `delta = 1/60` and `double` math. Fixtures generated by the
> JS `simulateShot` are the source of truth.

---

## 0. What the first 10 levels actually use

Verified by running `createLevelRuntime(0..9)` and inspecting every planet /
level field. The covered levels use **only**:

- One central sun at the origin `(0,0)`, stationary, gravity strength `20`.
- 1–5 planets per level, each with: circular **or** eccentric orbit
  (`orbitEccentricity` `0..0.18` in scope; levels 4/8/9, with level 9 reaching the
  `0.18` max — level 4 has `0.06`, level 8 `0.04`), spin, `gravity`, `falloff`,
  `landable` flag, optional `landingRadius`.
- Goal with `goalCenter`, `goalRadius`, `goalPullRadius`, `goalPullStrength`.
- Drag-to-launch, sun+planet gravity, goal pull, flight, collision, landing
  (anchored ball riding an orbiting/spinning planet), goal capture, out-of-bounds.

The following are **absent** in all 10 levels and are therefore **out of scope**
(see §16): moons (`orbitCenterIndex`/`orbitAround`), extra suns, binary systems,
portals, dust clouds, asteroids, meteors, pulsar jets, turrets, ice/lava/split
surfaces, flicker planets, red-giant/dying/supernova systems, goal-unlock relays,
ball heat (lava), goal open/close timers (see §7.4 — goal is *always open*).

`solveKeplerEquation` **IS** in scope because levels 4, 8, 9 have eccentric orbits.

## 1. Data source: RESOLVED runtime, not level definitions

C# receives each level as **resolved runtime data** exported *after*
`rotateLevelSourceGoalRight` + `createLevelRuntime` at `time = 0`
(`game-core.js:4305`). This means C# **never** performs:

- polar→cartesian conversion (`pointFromPolar`, `game-core.js:3051`),
- layout scaling (`scalePointFromSun`, `SYSTEM_LAYOUT_SCALE = 1`, no-op),
- radius scaling (`PLANET_RADIUS_SCALE = 0.5`) — **exported radii are already
  halved** (source `radius: 0.62` → runtime `radius: 0.31`). Same for
  `landingRadius` (`game-core.js:4350`).
- orbit-parameter derivation (`createOrbitDefaults`, `createSpinDefaults`).

C# **DOES** advance time-dependent state from the exported parameters: orbit
position/velocity, spin (for anchoring), goal timing. See §5–§7.

Exported per-planet orbit/spin fields are the runtime outputs, e.g. for level 0
planet 0: `orbitSemiMajor 5.356`, `orbitSemiMinor 5.356`, `orbitEccentricity 0`,
`orbitRotation 0.02268928…`, `orbitSpeed 0.01`, `orbitPhase 0`, `spinSpeed 0.01`.

## 2. Coordinate system, units, precision

- 2D plane, `x` right, `y` up. Units are abstract "world units".
- Angles in **radians** internally; some level fields are in **degrees**
  (`startAngleDeg`, launch preset `angleDeg`) — convert with `* Math.PI / 180`.
- Time in **seconds**.
- **All numbers are IEEE-754 `double`.** Use C# `double`. JS `Number` == `double`,
  so this is the whole point: match semantics exactly. Do **not** use `float`
  anywhere in the core.

## 4. Vector math helpers (`game-core.js:2942–2989`)

Use a mutable `struct`/`class Vec2 { double x, y; }`. Match these exactly:

| JS | Behavior |
|---|---|
| `vec(x=0,y=0)` | `new Vec2(x,y)` |
| `cloneVec(p)` | copy |
| `setVec(t,s)` | `t.x=s.x; t.y=s.y` |
| `clamp(v,min,max)` | `Math.Max(min, Math.Min(max, v))` |
| `addScaledVec(t,d,s)` | `t.x += d.x*s; t.y += d.y*s` (mutates `t`) |
| `distanceBetween(a,b)` | `Math.hypot(a.x-b.x, a.y-b.y)` |
| `lengthSq(v)` | `v.x*v.x + v.y*v.y` |
| `length(v)` | `Math.hypot(v.x, v.y)` |
| `normalize(v)` | if `length(v) < 0.000001` → `(0,0)`; else `(v.x/len, v.y/len)` |
| `directionFromAngleDeg(deg)` | `(cos(deg*π/180), sin(deg*π/180))` |
| `rotateVector(v, a)` | `(v.x·cos a − v.y·sin a, v.x·sin a + v.y·cos a)` (`:3263`) |

**`Math.hypot` gotcha (critical):** JS `Math.hypot` is *more accurate* than a
naïve `Math.Sqrt(dx*dx+dy*dy)` (it avoids intermediate over/underflow and uses a
correction). C# has no `Math.Hypot`. For magnitudes here (< ~30) the naïve
`sqrt` matches `Math.hypot` to within ~1 ULP, but this can drift over ~1000
frames. **Recommendation:** implement a `Hypot(dx,dy)` that mirrors the accurate
algorithm, OR accept a small parity tolerance (§15). Do **not** silently swap in
`Vector2.Distance` (that's `float`).

`clamp` note: JS `Math.min(max, x)` with `x = NaN` returns `NaN`; C# `Math.Min`
also propagates `NaN`. Matches. But NaN should never arise in-scope.

## 7. Time-dependent state — `setLevelTime` (`game-core.js:3810`)

`setLevelTime(level, time)` sets `level.time = time` and recomputes every dynamic
body. **For the first 10 levels the in-scope work reduces to: for each planet,
set its `position` from its orbit at `time`.** Full ordered behavior:

1. `level.time = time`.
2. `systemCenter = level.systemCenter ?? level.sun` → `(0,0)`.
3. `primarySunBody`: null in scope → skip (sun stays at `(0,0)`).
4. `extraSuns`: empty → skip.
5. Build a fresh orbit-state cache (`Map`), then **for each planet in index
   order**:
   - `planet.collisionPulse = 0` (cosmetic; ignore).
   - `orbitState = getOrbitState(level, planet.index, time, cache)` (§7.1).
   - `planet.position = orbitState.position`.
   - `planet.orbitCenter = orbitState.orbitCenter` (`(0,0)` in scope).
   - `updatePlanetCollapseState` → for a plain planet (no `redGiant`, no
     `fallIntoSunRadius`, not hidden) this just sets `active=true`,
     `infallFade=1`, `collapseState='stable'` (`:3696`). **No-op for scope.**
   - `updatePlanetFlickerState` → no `flicker` → sets steady defaults. **No-op.**
6. `separateActivePlanetOverlaps` → guarded by `level.systemState !== 'dying'`
   (`:3765`); in scope `systemState` is undefined → **returns immediately**.
7. Second pass of collapse/flicker updates → no-op.
8. portals/dustClouds/asteroids/meteorImpacts loops → all empty → skip.

**C# `SetLevelTime` reduces to:** `level.time = time;` then for each planet
`planet.position = GetOrbitState(level, i, time, cache).position;`. Keep the
`cache` so a planet is computed once per call (matters if you later add moons;
harmless now).

> Note: spin is **not** applied to planet position here. `spinSpeed` only affects
> the anchored ball (§12) and surface launch velocity (§9).

### 7.1 `getOrbitState(level, planetIndex, time, cache)` (`game-core.js:3596`)

Returns `{ position, velocity, orbitCenter }`.

1. If `cache` has `planetIndex`, return cached.
2. `orbitCenter = systemCenter` (clone), `centerVelocity = (0,0)`.
   - If `orbitCenterIndex != null` → recurse into parent (moons; **out of
     scope**, will not occur).
   - Else `getDynamicOrbitAnchorState` (`:3543`): with no `orbitAnchor` field it
     returns `{ position: systemCenter, velocity: (0,0) }`. In scope always
     `(0,0)`.
3. **Static guard:** if `!planet.orbitSemiMajor || !planet.orbitSpeed` (either is 0)
   → return `{ position: basePosition (non-moon), velocity: centerVelocity,
   orbitCenter }`. (All 10 levels have nonzero orbitSpeed, so this branch is not
   hit, but keep it.) NOTE: the JS source writes this guard as
   `!planet.orbitRadius || !planet.orbitSpeed` (game-core.js:3615); `orbitRadius`
   always equals `orbitSemiMajor` (game-core.js:3430) and leveldata exports only
   `orbitSemiMajor`, so port the guard against `orbitSemiMajor`.
4. Finite-difference velocity with `dt = 0.0005`:
   ```
   meanAnomaly     = wrapAngleRad(orbitPhase + time*orbitSpeed)
   nextMeanAnomaly = wrapAngleRad(orbitPhase + (time+dt)*orbitSpeed)
   offset     = getOrbitOffset(planet, meanAnomaly, time)
   nextOffset = getOrbitOffset(planet, nextMeanAnomaly, time+dt)
   velocityOffset = (nextOffset - offset) / dt
   position = orbitCenter + offset
   velocity = centerVelocity + velocityOffset      // centerVelocity=(0,0) in scope
   ```
5. Cache and return.

`wrapAngleRad(a)` (`:3147`): `turn = 2π; ((a % turn) + turn) % turn` → result in
`[0, 2π)`. **`%` here is the JS remainder operator; C#'s `%` on `double` has the
same sign-of-dividend semantics, so this ports verbatim.** Do **not** use
`Math.IEEERemainder`.

### 7.2 `getOrbitOffset(planet, anomaly, time)` (`game-core.js:3566`)

```
if (!orbitSemiMajor || !orbitSpeed) return (0,0);
decayScale = 1                       // getOrbitDecayScale: no orbitDecayRate in scope (:3291)
a = orbitSemiMajor * decayScale
b = orbitSemiMinor * decayScale

if (orbitEccentricity < 0.000001):   // circular
    return rotateVector( (cos(anomaly)*a, sin(anomaly)*a), orbitRotation )

E = solveKeplerEquation(anomaly, orbitEccentricity)
return rotateVector( (a*(cos(E) − e), b*sin(E)), orbitRotation )
```

where `e = orbitEccentricity`, `orbitRotation` defaults to `0` if absent.

### 7.3 `solveKeplerEquation(M, e)` (`game-core.js:3272`) — Newton's method

```
if (e < 0.000001) return M;
E = M;
for (i = 0; i < 8; i++):
    delta = (E − e*sin(E) − M) / max(0.000001, 1 − e*cos(E));
    E -= delta;
    if (abs(delta) < 0.000001) break;
return E;
```

Exact loop count / break condition matters for parity. Reproduce verbatim.

### 7.4 Goal open/close — effectively a no-op

`GOAL_ALWAYS_OPEN = true` is hard-coded (`:40`). Consequences (`:3854–3903`):

- `getGoalCloseTime(level)` → `+Infinity`.
- `getGoalRemainingTime` → `+Infinity`.
- `getGoalRemainingFraction` → `+Infinity`.
- **`isGoalOpen(level, time)` → always `true`** (after the `goalUnlockRequired &&
  !goalUnlocked` guard, which is false in scope).

**C# in scope:** implement `IsGoalOpen(...) => true`. Every `isGoalOpen` call in
`stepBall`/`sampleBallAcceleration` therefore short-circuits to "open", and the
`goal-closed` crash branch (`:4942`) is **unreachable**. Keep the field
`goalOpenSeconds` in data but never gate on it. (If you want future-proofing,
implement the real formula behind a `GOAL_ALWAYS_OPEN` flag defaulting `true`.)

### 7.5 `getPlanetVelocity(level, i, time)` (`game-core.js:3972`)

Returns `(0,0)` if planet missing / `collapseState==='consumed'` / `active===false`
(none in scope), else `getOrbitState(level, i, time).velocity`. Used at launch
(§9) to inherit the launch planet's orbital velocity.

## 8. Gravity sampling

### 8.1 `samplePlanetGravity(level, point)` (`game-core.js:4809`)

Accumulate `netGravity` (starts `(0,0)`):

**Planets** — for each planet, in index order:
```
if (planet.active === false || planet.hidden) continue;     // never in scope
toPlanet  = planet.position − point;
distance  = max(length(toPlanet), 0.001);
if (distance >= planet.falloff) continue;                   // HARD cutoff
pull      = planet.gravity * 2.35 / (distance*distance + 0.22);
dir       = normalize(toPlanet);
netGravity += dir * pull;
```
Note `distance` uses the clamped value but the `>= falloff` test uses the same
clamped `distance`. The `0.22` softening is inside the denominator.

**Sun(s)** — build the solar body list: primary sun `{ position: level.sun,
gravityStrength: level.sunGravityStrength ?? 20 }` plus `extraSuns` (empty). For
each with `gravityStrength > 0`:
```
toSun    = solar.position − point;
distance = max(length(toSun), 0.001);
pull     = gravityStrength * 5 / (distance*distance + 3.4);   // SOFTENING=3.4, no cutoff
dir      = normalize(toSun);
netGravity += dir * pull;
```
Return `netGravity`.

### 8.2 `sampleBallAcceleration(level, point)` (`game-core.js:4859`)

```
acc = samplePlanetGravity(level, point);
toGoal = goalCenter − point;
goalDistance = max(length(toGoal), 0.001);
if (isGoalOpen(...) /* always true */ && goalDistance < goalPullRadius):
    pull = goalPullStrength / (goalDistance*goalDistance + 0.38);
    acc += normalize(toGoal) * pull;
return acc;
```

Goal pull **is in scope** (all 10 levels set `goalPullRadius`/`goalPullStrength`).

## 9. Launch math

### 9.1 Speed / velocity (`game-core.js:4799–4807`)

```
launchSpeedForDrag(dragPower) = min(11.8, 1.9 + dragPower*3.4)     // LAUNCH_MAX/BASE/DRAG
launchVelocity(direction, dragPower):
    n = normalize(direction);
    s = launchSpeedForDrag(dragPower);
    return (n.x*s, n.y*s);
```

`dragPower` is the drag stretch length, clamped to `[~0, MAX_DRAG_DISTANCE=2.75]`
by the UI; launch preset `power` **is** the `dragPower`. `MAX_DRAG_DISTANCE`
caps drag input, not the velocity (velocity is capped by `LAUNCH_MAX_SPEED`).

### 9.2 Composite launch velocity (parity path, `simulateShot` `:5212`)

At the instant of launch the ball inherits the planet's motion:
```
relative = launchVelocity( (cos(shot.angle), sin(shot.angle)), shot.dragPower );
bodyVel  = anchorPlanetIndex != null ? getPlanetVelocity(level, anchorPlanetIndex, ball.time) : (0,0);
surfVel  = anchorPlanetIndex != null ? getPlanetSurfaceVelocity(level, anchorPlanetIndex, ball.anchorNormal, /*ball=*/null) : (0,0);
ball.velocity = relative + bodyVel + surfVel;
ball.launchGracePlanetIndex = ball.anchorPlanetIndex;
ball.anchorPlanetIndex = null;
ball.anchorNormal = null;
```
`shot.angle` is an **absolute launch direction in radians** (not relative to the
planet). For a launch preset, `shot.angle = angleDeg * π/180`. `simulateShot`
does **not** apply the UI's `constrainLaunchDirection` — the raw angle is used.

`getPlanetSurfaceVelocity(level, i, anchorNormal, ball)` (`:4056`):
```
if (planet missing || active===false || (spinSpeed==0 && slideAngularSpeed==0)) return (0,0);
normal  = normalize(anchorNormal ?? (1,0));
tangent = (−normal.y, normal.x);
speed   = getBallSurfaceRadius(planet) * (spinSpeed + getPlanetSlideAngularSpeed(planet, ball));
return tangent * speed;
```
`getPlanetSlideAngularSpeed` is `0` in scope (ice only; `:4032`). So
`speed = getBallSurfaceRadius(planet) * spinSpeed`.

`getBallSurfaceRadius(planet)` (`:3905`):
`planet.radius + 0.28 + 0.03 + (ice ? −0.01 : 0)` → in scope `radius + 0.31`.

## 10. `stepBall(level, ball, delta)` — full ordered walkthrough (`game-core.js:4899`)

Semi-implicit (symplectic) Euler: **acceleration updates velocity first, then
position moves.** Friction is applied **after** contact resolution. Execute in
**exactly** this order; the first branch that returns wins.

```
STEP 0 — anchor-consumed guard (:4900):
    if anchorPlanetIndex set AND anchored planet is consumed/destroyed/inactive:
        clear anchor, zero velocity, return crash{reason: planet-consumed|planet-vanished|meteor}.
    // Not triggered in scope (planets always active). Keep the guard.

STEP 1 — pre-move settle (:4930):
    if lengthSq(velocity) < 0.000001 AND canBallSettle(level, ball):
        zero velocity; return { type:'settled' }.   // note: no eventState on this early one

STEP 2 — advance time (:4936):
    nextTime = (ball.time ?? level.time ?? 0) + delta;
    setLevelTime(level, nextTime);      // planets move to nextTime
    ball.time = nextTime;
    ball.portalCooldown = max(0, portalCooldown − delta);
    updateBallHeat(level, ball, delta); // in scope: cools heat toward 0; return value IGNORED here

STEP 3 — goal-closed crash (:4942):
    if (!goalUnlockRequired || goalUnlocked) AND !isGoalOpen(level, ball.time):
        crash 'goal-closed'.
    // UNREACHABLE in scope (isGoalOpen always true). Implement but it never fires.

STEP 4 — integrate velocity (:4949):
    acceleration = sampleBallAcceleration(level, ball.position);   // planets already at nextTime
    ball.velocity += acceleration * delta;

STEP 5 — pre-move goal capture (:4953):
    toGoal = goalCenter − ball.position;
    goalDistance = max(length(toGoal), 0.001);
    if isGoalOpen(...) AND goalDistance < goalRadius * 0.95:   // GOAL_CAPTURE_RATIO
        zero velocity; return { type:'goal' }.

STEP 6 — integrate position (:4963):
    previousPosition = clone(ball.position);
    ball.position += ball.velocity * delta;      // addScaledVec

STEP 7 — portal contact (:4966):  resolvePortalContact → null in scope (no portals).

STEP 8 — post-move goal capture (:4968):
    postPortalGoalDistance = max(distanceBetween(ball.position, goalCenter), 0.001);
    if isGoalOpen(...) AND postPortalGoalDistance < goalRadius * 0.95:
        zero velocity; return { type:'goal' }.

STEP 9 — sun contact (:4976):  resolveSunContact(level, ball, previousPosition)  (§10.1).

STEP 10 — turret contact (:4982):  null in scope.

STEP 11 — planet contact (:4988):  resolvePlanetContact(level, ball)  (§11).

STEP 12 — asteroid contact (:4994):  null in scope.

STEP 13 — meteor contact (:5000):  null in scope.

STEP 14 — friction (:5006):
    friction = pow(0.992, delta*60) * getDustDragFactorAtPoint(...);  // dust=1.0 in scope
    ball.velocity *= friction;

STEP 15 — out of bounds (:5010):
    if abs(position.x) > 13.8 OR abs(position.y) > 10:
        zero velocity; return crash 'bounds'.

STEP 16 — post-move settle (:5020):
    if length(velocity) < 0.055 AND canBallSettle(level, ball):
        zero velocity; return { type:'settled', ... }.

STEP 17: return { type:'flying' }.
```

`canBallSettle(level, ball, acc=null)` (`:4894`):
`length(acc ?? sampleBallAcceleration(level, ball.position)) < 0.04`.

`getBallFriction` (`:4890`): `pow(BALL_FRICTION_BASE, delta*60) * dustFactor`.
With `delta = 1/60`, `delta*60 = 1`, so `friction = 0.992 * 1.0 = 0.992` per step
in scope. **Use `Math.Pow`, not `**`.**

`updateBallHeat` (`:3935`) in scope (no lava anchor, or flying): `heat -=
BALL_HEAT_COOL_RATE_FLIGHT(0.72) * delta` (or `_ANCHORED 0.38` when anchored),
clamped `[0,1]`. Starts at 0 → stays 0. Returns `null` (no crash). The return is
ignored inside `stepBall`.

## 11. `resolvePlanetContact` + landing (`game-core.js:4583`)

Iterate planets in **index order**; first hit wins.

```
for index in 0..N-1:
    planet = planets[index];
    if planet.hidden: continue;                    // never in scope
    if planet.active === false:                    // never in scope
        if launchGracePlanetIndex === index: launchGracePlanetIndex = null;
        continue;

    toPlanet = planet.position − ball.position;
    distance = max(length(toPlanet), 0.001);
    touchRadius   = planet.radius + 0.28 * 0.92;               // PLANET_COLLISION_PADDING
    landingRadius = planet.landingRadius ?? getBallSurfaceRadius(planet);

    // (A) clear launch grace once ball leaves the launch planet's landing shell:
    if launchGracePlanetIndex === index AND distance > landingRadius + 0.03:  // PLANET_LANDING_PADDING
        launchGracePlanetIndex = null;

    // (B) landable contact:
    if planet.landable AND distance <= touchRadius:
        landingDirection = getLandingDirection(ball, planet);
        if !isPlanetLandingSide(planet, landingDirection, ball.time):   // split only; TRUE in scope
            zero velocity; return crash 'split-side';                   // unreachable in scope
        landBallOnPlanet(ball, planet, index);                          // §11.2
        goalUnlocked = planet.goalUnlock && goalUnlockRequired && !goalUnlocked;  // false in scope
        return { type:'landed', planetIndex:index, planetName, goalUnlocked };

    // (C) non-landable (or landable side already handled) hard contact:
    if distance <= touchRadius:
        zero velocity; return crash 'planet';
return null;
```

**Critical subtlety about `launchGracePlanetIndex`:** it is *not* checked in the
landable/crash conditions above. Landing/crash can happen even on the grace
planet the same frame IF `distance <= touchRadius`. The grace index only gets
*cleared* (branch A) once the ball is beyond `landingRadius + 0.03`. In practice
the launch velocity pushes the ball outward, so branch A fires before the ball
could re-touch; but reproduce the code as written — do **not** add an early
`continue` for the grace planet. (The grace mechanic matters for hazards like
turrets/sun-sight, out of scope, but keep the field bookkeeping exact.)

### 11.1 `getLandingDirection(ball, planet)` (`game-core.js:4522`)

```
fromPlanet = ball.position − planet.position;
if lengthSq(fromPlanet) > 0.000001: return normalize(fromPlanet);
if lengthSq(ball.velocity) > 0.000001: return normalize(−ball.velocity);
return (1,0);
```

### 11.2 `landBallOnPlanet(ball, planet, planetIndex)` (`game-core.js:4552`)

```
landingDirection = getLandingDirection(ball, planet);
surfaceRadius    = getBallSurfaceRadius(planet);              // radius + 0.31
ball.position    = planet.position + landingDirection * surfaceRadius;
ball.velocity    = (0,0);
ball.landingCount += 1;
ball.launchGracePlanetIndex = null;
ball.anchorPlanetIndex = planetIndex;
ball.anchorNormal = landingDirection;
ball.anchorSinceTime = ball.time ?? 0;
ball.portalCooldown = 0;
```

**Landing has no speed threshold and no bounce.** Any landable contact within
`touchRadius` snaps the ball to the surface and anchors it (velocity zeroed).
Non-landable planets always crash. There is no "land vs bounce vs crash by speed"
logic in this codebase (`DEFAULT_PLANET_LANDING_SPEED = 3.2` is authoring-only and
unused by the sim). `ICE_PLANET_LANDING_PADDING` only applies to ice surfaces
(out of scope).

`isPlanetLandingSide` (`:2996`): with no `splitSurface`, returns
`Boolean(planet.landable)` → always the landable flag. In scope always `true` for
the (B) branch (we only enter it when `planet.landable`).

`findContainingLandingPlanetIndex` (`:4567`) is used by `simulateShot` to seed the
grace index when `anchorPlanetIndex` is null; see §14.

## 12. `advanceBallAnchor` — riding an orbiting/spinning planet (`game-core.js:3981`)

Called each frame while the ball is anchored (during the pre-launch `waitTime`
window, and in the live game between shots). Returns a crash result or `null`.

```
if anchorPlanetIndex == null: return null;
planet = planets[anchorPlanetIndex];
if planet missing || collapseState==='consumed' || active===false:
    clear anchor, zero velocity, return crash{planet-consumed|planet-vanished|meteor}; // not in scope

previousPosition = clone(ball.position);

if planet.spinSpeed:
    ball.anchorNormal = normalize( rotateVector(ball.anchorNormal ?? (1,0), planet.spinSpeed * delta) );
slideAngularSpeed = getPlanetSlideAngularSpeed(planet, ball);   // 0 in scope (ice only)
if slideAngularSpeed:
    ball.anchorNormal = normalize( rotateVector(ball.anchorNormal ?? (1,0), slideAngularSpeed * delta) );

syncBallToAnchor(level, ball);            // reposition ball on the (moved) planet surface
resolveMeteorContact(...) → null;         // out of scope
resolveTurretSightContact(...) → null;    // out of scope
return updateBallHeat(level, ball, delta); // null in scope
```

`syncBallToAnchor(level, ball)` (`:4535`):
```
if anchorPlanetIndex == null: return;
planet = planets[anchorPlanetIndex];
if planet missing/consumed/inactive: ball.anchorPlanetIndex = null; return;
n = normalize(ball.anchorNormal ?? (1,0));
r = getBallSurfaceRadius(planet);
ball.position = planet.position + n * r;
```

**Order matters:** rotate `anchorNormal` by `spinSpeed*delta` (then slide) **then**
`syncBallToAnchor` reads the *already-advanced* `planet.position` (planet was moved
by the `setLevelTime` call that precedes `advanceBallAnchor` in the caller — see
§14 wait loop). So the anchored ball both revolves with the planet's orbit
(position) and rotates around it with the planet's spin (normal).

## 13. Goal capture condition

`GOAL_CAPTURE_RATIO = 0.95`. Capture (`type:'goal'`) fires when
`goalDistance < level.goalRadius * 0.95` at either the pre-move check (STEP 5,
using pre-integration position) or the post-move check (STEP 8). `isGoalOpen` is
always true in scope so the only gate is the distance. On capture, velocity is
zeroed and the shot ends with outcome `goal`.

Goal **pull** (an acceleration, §8.2) uses `goalPullRadius`/`goalPullStrength`;
goal **capture** (ending the shot) uses `goalRadius * 0.95`. These are different
radii — keep them distinct.

## 14. `simulateShot(level, shot, options)` — parity contract (`game-core.js:5074`)

The parity runner must reproduce this exactly.

### 14.1 Inputs

```
shot = { angle: double (radians, absolute), dragPower: double (== preset.power), waitTime?: double }
options:
    delta         = options.delta ?? 1/60          // DEFAULT 1/60
    maxTime       = options.maxTime ?? 20
    startTime     = options.startTime ?? 0
    waitTime      = shot.waitTime ?? options.waitTime ?? 0
    captureFrames = options.captureFrames === true  // false for parity summaries
    anchorPlanetIndex = options.anchorPlanetIndex ?? level.startPlanetIndex ?? null
    anchorNormal  = options.anchorNormal ?? directionFromAngleDeg(level.startAngleDeg ?? 180)
    startPosition = options.startPosition ?? level.startAnchor
```

### 14.2 Procedure

```
setLevelTime(level, startTime);           // planets to t=startTime (0)
ball = {
    position: clone(startPosition),
    velocity: (0,0),
    time: startTime,
    landingCount: options.landingCount ?? 0,
    launchGracePlanetIndex: anchorPlanetIndex ?? findContainingLandingPlanetIndex(level, startPosition),
    anchorPlanetIndex,
    anchorNormal: clone(anchorNormal),
    heat: options.heat ?? 0,
};
if (anchorPlanetIndex != null) syncBallToAnchor(level, ball);   // snap to planet surface at t=startTime

// ---- wait phase (skipped when waitTime <= 0; all 10 presets have waitTime 0) ----
if (waitTime > 0):
    // non-captureFrames path (parity default):
    launchTime = startTime + waitTime;
    setLevelTime(level, launchTime);
    ball.time  = launchTime;
    if (anchorPlanetIndex != null):
        anchorResult = advanceBallAnchor(level, ball, waitTime);   // SINGLE step of size waitTime
        if (anchorResult?.type === 'crash'):  return result{outcome:'crash', ...};  // §14.3

// ---- goal-open gate (always passes in scope) ----
if (!isGoalOpen(level, ball.time)):  return result{outcome:'crash', reason:'goal-closed', ...};

// ---- launch (§9.2) ----
relative = launchVelocity((cos(shot.angle), sin(shot.angle)), shot.dragPower);
bodyVel  = anchorPlanetIndex != null ? getPlanetVelocity(level, anchorPlanetIndex, ball.time) : (0,0);
surfVel  = anchorPlanetIndex != null ? getPlanetSurfaceVelocity(level, anchorPlanetIndex, ball.anchorNormal /*, ball=null */) : (0,0);
ball.velocity = relative + bodyVel + surfVel;
ball.launchGracePlanetIndex = ball.anchorPlanetIndex;
ball.anchorPlanetIndex = null;
ball.anchorNormal = null;

// ---- flight loop ----
time = 0; steps = 0;
minGoalDistance = distanceBetween(ball.position, goalCenter);
minPlanetClearance = +Infinity;
while (time < maxTime):
    minGoalDistance = min(minGoalDistance, distanceBetween(ball.position, goalCenter));
    for each planet with active !== false:
        clearance = distanceBetween(ball.position, planet.position) − (planet.radius + 0.28*0.92);
        minPlanetClearance = min(minPlanetClearance, clearance);
    result = stepBall(level, ball, delta);
    time  += delta;
    steps += 1;
    if (result.type !== 'flying'):  return result{outcome: result.type, ...};
return result{outcome:'timeout', ...};
```

> **`waitTime` path note (game-core.js:5117–5155).** The pseudocode above shows the
> `captureFrames=false` wait phase: one `setLevelTime(startTime+waitTime)` + a
> **single** `advanceBallAnchor(level, ball, waitTime)`. The fixture-generation
> path (`captureFrames=true`, the path that emits fixtures, game-core.js:5119)
> instead **sub-steps the wait phase by `delta` in a loop** (`step = min(delta,
> remainingWait)`, advancing `setLevelTime`/`advanceBallAnchor` by `step` and
> pushing a frame each iteration). For any nonzero `waitTime` these two paths can
> diverge (spin/orbit is advanced in one big step vs. many `delta` steps); they
> **coincide only at `waitTime = 0`**, where neither loop body runs. All level 0–9
> presets have `waitTime = 0`, so the distinction is moot in scope — but if you
> ever add a `waitTime > 0` fixture, the C# parity runner MUST reproduce the
> `captureFrames` sub-stepping loop, not the single-step form.

**Important ordering inside the loop:** `minGoalDistance` and `minPlanetClearance`
are sampled **before** `stepBall` advances the frame (they use the *previous*
frame's position and the *previous* frame's planet positions). `time` and `steps`
increment **after** `stepBall`. Reproduce this exactly if you compare those
metrics.

### 14.3 Result object (fields the runner should compare)

```
outcome:        'goal' | 'landed' | 'settled' | 'crash' | 'timeout'
reason:         string ('' | 'planet' | 'sun' | 'bounds' | 'goal-closed' | ...)
planetIndex:    int|null
planetName:     string
waitTime:       double
landingCount:   int
time:           double       // = steps * delta at return (flight loop time)
steps:          int
finalTime:      double       // ball.time ?? startTime + time
anchorPlanetIndex: int|null
anchorNormal:   {x,y}|null
heat:           double
minGoalDistance:   double
minPlanetClearance: double
finalPosition:  {x,y}
launchState:    ball snapshot at launch (nullable)
eventState / displayEventState: snapshots for rendering (nullable)
```

Outcome values: `stepBall` returns `type` ∈ {`flying`,`settled`,`goal`,`landed`,
`crash`}; the loop maps non-`flying` to `outcome`. `crash.reason` in scope can be
`planet`, `sun`, `bounds` (and the unreachable `goal-closed`, `split-side`,
`pulsar`). `timeout` when the loop exhausts `maxTime`.

For parity, the primary comparison keys are: **`outcome`, `reason`, `steps`,
`landingCount`, `anchorPlanetIndex`, and `finalPosition` (within tolerance)**.
`minGoalDistance`/`minPlanetClearance` are secondary. Frame-by-frame comparison
(`captureFrames: true`) gives the tightest test; each frame captures
`{position, velocity, time, anchorPlanetIndex, landingCount}` (`:5103`).

**Reference fixture (sanity check):** level 0, `shot = { angle: −1.4·π/180,
dragPower: 1.38, waitTime: 0 }`, default options →
`outcome='goal'`, `steps=128`, `time≈2.1333`,
`finalPosition≈(9.8609230, 0.0058106)`, `minGoalDistance≈0.5343`,
`landingCount=0`.

### 14.4 Live game vs parity core

The live game loop uses a **fixed `PHYSICS_STEP = 1/120`** with an accumulator
(`main.js:462`, `:3129`), not `1/60`. **Parity fixtures use `simulateShot`'s
`1/60`.** The C# core should expose the `simulateShot` semantics for the parity
runner; the interactive Unity layer may choose its own step, but any automated
parity test must call the core with `delta = 1/60` to match exported fixtures.
`reverseStepBall` (`:5030`, rewind/undo) is **out of scope**.

## 15. JS → C# numeric gotchas (must-read)

1. **`double` everywhere.** No `float` in the core. `Vector2`/`Mathf` are `float`
   — do not use them. Use `System.Math` (`double`) and a custom `Vec2`.
2. **`Math.hypot`** (used by `length`/`distanceBetween`) has no C# equivalent;
   naïve `Math.Sqrt(dx*dx+dy*dy)` differs by ~1 ULP and can drift over a long
   trajectory. The parity tolerance contract — exact `outcome`/`reason`/`steps`/
   `landingCount` (with a ±1 `steps` allowlist escape hatch), per-frame position/
   velocity `|Δ| ≤ 1e-6`, and the "implement a V8-equivalent `Hypot` before any
   per-level 1e-4 relaxation" rule — is defined **once** in `spec-leveldata.md`
   §7.4. Follow it there; do not restate different numbers here.
3. **`Math.atan2(y, x)`** → `Math.Atan2(y, x)` (same arg order, same branch cuts).
   Used in `getLandingDirection`? No — but in helpers/exporter. Safe.
4. **`%` remainder:** JS `%` and C# `%` on `double` both take the **sign of the
   dividend**. `wrapAngleRad`'s `((a % turn) + turn) % turn` ports verbatim.
   **Do NOT use `Math.IEEERemainder`** (rounds to nearest, different sign).
5. **`??` (nullish coalescing):** applies only for `null`/`undefined`, **not** for
   `0`/`false`/`NaN`. E.g. `planet.orbitSpeed ?? x` keeps `0`. Port with explicit
   `HasValue`/nullable checks, not `?? ` on non-nullable defaults that would swap
   a real `0`. Where the code does `!planet.orbitRadius || !planet.orbitSpeed`,
   that is a **falsy** test (`0`, `NaN`, `null`, `undefined` all falsy) — port as
   `orbitSemiMajor == 0 || orbitSpeed == 0` (plus null if nullable). (`orbitRadius`
   in the JS source always equals the exported `orbitSemiMajor`; see §5.2/§7.1.)
6. **`**` operator** → `Math.Pow`. Appears in friction `pow(0.992, delta*60)` and
   `orbitSemiMinor = a*sqrt(1−e²)` (already exported).
7. **`Math.sign(x)`**: JS returns `-0`/`0`/`+1`/`-1`; C# `Math.Sign` returns `int`
   and **throws on `NaN`**. Only used in authoring (`createSpinDefaults`), which
   C# does not run. Ignore.
8. **`Number.POSITIVE_INFINITY`** → `double.PositiveInfinity`. Comparisons like
   `x < +Infinity` behave identically.
9. **Falsy guards on objects:** `if (planet.spinSpeed)` is false when `spinSpeed`
   is `0` (or `NaN`). Port as `if (planet.spinSpeed != 0)`.
10. **Array/loop order is load-bearing.** Planets are iterated in index order in
    gravity, contact, and clearance loops; the **first** returning branch wins.
    Never reorder.
11. **Mutation semantics.** JS objects are references; `setLevelTime` mutates
    `planet.position` in place each frame and `stepBall` mutates `ball`. Keep the
    same in-place mutation so intra-frame reads (e.g. gravity sampled *after*
    `setLevelTime`) see advanced planet positions.
12. **Epsilons are literal.** `0.000001`, `0.001`, `0.0005`, `0.22`, `0.38`,
    `0.92`, `0.95` — copy exactly; they change results.
